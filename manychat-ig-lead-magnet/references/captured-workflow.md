# Sanitized captured-workflow lessons

These lessons come from the existing recorded workflow. Private screenshots, account IDs, automation IDs, integration IDs, names, run counts, and live-state snapshots are omitted. This reference is not a coordinate replay or a claim that a particular flow is currently active.

Current default: explicit newsletter signup is required before resource delivery; consent must be unambiguous and subscription verified. Earlier optional-consent or email-only observations are historical, not current rollout instructions. Follow `email-and-story-checklist.md`.

## Recorded operating sequence

1. Gather the authorized source and create a branded downloadable resource. Keep the resource promise clear and inspect the actual file. The observed PDF control had a 25 MB maximum; verify the current limit before uploading.
2. Open the intended ManyChat account. Reconnect prompts require the user to complete authentication. Resolve workspace identity and connected Instagram account rather than trusting a saved connection label.
3. Find an appropriate existing Instagram comment or newsletter automation under Automation / My Automations. Keyword and Basic views may help locate it.
4. Under the exact rollout authorization, duplicate the working automation, rename it, and check whether its trigger is enabled. Saving a copied trigger was observed to activate it; do not assume copying or saving is a harmless offline draft.
5. Configure intentional keywords and the exact post/reel scope. Prefer visible labels over cached coordinates. Preserve the original flow unless replacement is authorized.
6. Edit the resource-specific DM, attachment, email question, and tracking fields. Keep copied alternate paths and reminders under review so they do not send the old offer.
7. Verify saved content, publication, and trigger activation separately. A click or Saved indicator does not establish a live, working integration.

## Email integration lessons

- Email capture alone does not necessarily invoke the downstream integration. Verify the intended event after valid email input and newsletter consent.
- Inspect consumers before changing a shared email mapping. A newer system-email field may be empty in legacy flows even when those flows collect email. Prepare a separately authorized migration when needed.
- When email is required, verify required input, storage, consent, successful-input routing, and delivery. Do not silently reactivate unsubscribed contacts.
- Downstream signup can be asynchronous. Distinguish request acceptance from final subscription and delivery. Do not promise completion merely because an API accepted the request.
- Inspect bounded history before alleging data loss or building a replacement integration. Historical successful runs do not test a newly changed flow.

## Useful UI anchors and evidence

Observed anchors included Automation, Keywords, Basic, My Automations, Duplicate, + Keyword, Continue, PDF, Saved, and Update. Re-read the current UI before acting; these are observations, not guaranteed current labels.

For an authorized replacement, verify the intended integration and resource, stop the old competing trigger only within scope, publish the reviewed content, enable the intended trigger, and read back both states. Record account, post scope, keywords, event, and exact resource URL in the private project workspace.

Keep configuration review, publication, enabled trigger, successful downstream run, and a full authorized Instagram-to-delivery test as distinct evidence levels. No end-to-end proof is bundled with this skill.

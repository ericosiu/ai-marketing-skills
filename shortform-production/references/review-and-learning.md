# Review and learning

## Production review

Use the creator's existing shortform editorial eval. Do not create a competing score to make the candidate pass. Fix these demonstrated defects before release:

- First four seconds communicate one promise without chat flashes or competing layouts.
- Captions and comment prompt are readable at 360 px phone width, with sufficient contrast and stable geometry.
- No duplicate identity label, extreme face crop, clipped letters, or covered claim qualifier.
- Brand logos land on the spoken name. Every evidence crop is complete and legible. Diagrams are not represented as actual interfaces.
- Continuous listening review catches awkward joins, sync delay, pops, clipped words, and unnatural pauses. A successful decode is insufficient.
- The caption hook is paid off by the clip. Its CTA matches the recording and actual offered resource; verify an existing fulfillment mechanism when authorized, but don't create or claim a new one.

Save the final file hash, technical checks, and timestamped editorial observations. Mark unavailable audible playback or missing proof explicitly. Do not turn user style approval, sampled frames, audio correlation, or a successful API upload into an invented editorial score.

For technical verification, use `video-use`'s export and audio-alignment helpers when installed, with the actual source fps/geometry. Preserve PCM timing and confirm camera frames against the source. Low audio correlation is inconclusive. Every final revision needs fresh review evidence.

## One asset, one learning record

Keep a JSON or table row with asset ID/hash, source timestamps, format, hook text/treatment, style version, caption, CTA, audience/account, post ID, publication time, and duration. Record observations at comparable ages (proposed: 24h, 72h, 7d) only when data access or follow-up is authorized. These checkpoints do not create an automation.

Fields: observed_at, age_hours, reach, plays, average_watch_seconds, three_second_views, starts, completions, shares, saves, CTA_comments, qualified_responses, and source. Missing fields are null, never zero. Do not assume Metricool exposes three-second retention for Instagram; verify provider availability before choosing it as a primary metric.

Only calculate a rate from compatible numerators/denominators supplied by the same source and definition. Document replay handling and attribution limits. If three-second retention is unavailable, use supported watch-time/completion measures and report that early retention could not be measured directly.

Compare similar topics, duration, audience, placement, and post age. Keep organic and paid outcomes separate. Separate hook outcomes from downstream CTA outcomes. One post gives a lead for the next experiment; promote a house rule only after repeated comparable evidence, with sample size and uncertainty visible.

## Feedback to action

- Weak opening comprehension: simplify the promise/evidence, then make another four-second preview.
- Strong opening, weak completion: inspect where explanation slows or the payoff arrives late.
- Good viewing, weak saves/shares: make the takeaway more useful or specific.
- Strong CTA comments, weak qualified responses: inspect promise-to-resource fit and verified fulfillment.

Store the creator's preferences separately from performance findings. Never discard a clear human preference because one unrelated post received more views.
